# 2026-10-01 — Session 1: `laya-router` bootstrap and first real run

## Scope

Create `laya-router`: a generic, domain-free text-to-label router over Laya
(MIT, public, under `gia-uh`). Implement everything in one turn.

## Work done

- **Repo** `gia-uh/laya-router` (public, MIT, © GIA-UH + Syalia S.R.L.).
- Package `src/laya_router/`: `Category`/`load_labels` (consumer data),
  `Engine` protocol + `LayaEngine` (lazy import) + injectable fake,
  `Classifier`/`Classification`, `metrics` (accuracy, confusion matrix,
  threshold↔coverage), and a `classify`/`evaluate` CLI.
- `docs/DESIGN.md`; README with usage, the out-of-scope caveat and measured CPU
  numbers; Makefile (`make ci`), CI, integration marker.
- **CPU-only torch**: `laya` pulls `torch`, whose default wheels are multi-GB
  CUDA. `torch` is declared directly and pinned to the PyTorch CPU index, so the
  env is ~1 GB with no `nvidia-*` (5.4 GB → 986 MB).

## Logging added

- `laya_router.classifier`: `classified label= confidence= below_threshold=`;
  `laya_router.engine`: `laya load` / `laya scored`.

## Tests run

- `make ci` → ruff/format/pyright clean, **20 passed** (fast suite, fake engine,
  no model).
- **Real Laya on CPU** (multilingual checkpoint, ~650 MB): classified four texts
  → `to_do`/`reminder`/`idea` at ~1.0 confidence, **~110–130 ms** per call.

## Decisions taken

- Engine is injected; production uses Laya, tests use a fake → the gate never
  downloads a model.
- `below_threshold` is informative, not prescriptive: always return the best
  label plus the flag; the consumer decides. Documented the out-of-scope caveat.
- CPU-only torch by default (no CUDA payload).

## Known issues / open points

- The Xet download path hung after an interrupted transfer; disabling it
  (`HF_HUB_DISABLE_XET=1`) resumed fine. Worth documenting for slow hosts.
- Out-of-scope text can still get a moderate-confidence label; the threshold is
  the answer. Consider an explicit "none" option later if it matters.

## Next steps

- Add a small `labels.yaml` + `eval.jsonl` example and a real accuracy number on
  a consumer domain (e.g. invox pipelines) — as a *consumer*, not in this repo.
- Publish a first tag once the API settles.

# 2026-10-01 — Session 2: models and the HTTP service in one Makefile

## Scope

Make the two modes of use — the embedded library and the `laya-serve` HTTP
service — symmetric and reproducible, with one Makefile and a shared model.

## Work done

- **Model lifecycle is explicit and shared**: `make models-pull MODEL=…`,
  `models-list`, `models-path`, `models-rm`. The library and the service read the
  same Hugging Face cache, so the download happens once and both modes run
  offline afterwards.
- **Service targets**: `serve-up` (background, `LAYA_MODELS=$MODEL`,
  `LAYA_PRELOAD=1`, `LAYA_API_KEY`, waits until it answers), `serve-down`,
  `serve-logs`, `serve-wait`, `serve-smoke` (asserts **401 without token** and a
  real `choice` **with token**).
- **When the model is missing**, the consuming targets fail with a clear hint
  (`make models-pull MODEL=…`) instead of downloading silently (`models-check`).
- **`classify` target**: real classification from the library against the chosen
  `MODEL` (`LAYA_ROUTER_MODEL` flows into the engine).
- **`docs/SERVE.md`**: the contract (`POST /v1/systemone`), the raw command, the
  server's environment variables, the auth model and a real response.
- **README** section for both modes; `.gitignore` now covers `.serve-venv/` and
  `*.log` (a leftover manual venv from exploration).

## Logging added

- None (Makefile/docs).

## Tests run

- `make ci` → ruff/format/pyright clean, **20 passed** (fast, no model, no network).
- `make models-list` → `encoder, multilingual, tokenizer, typed-decisions` cached.
- `make models-check MODEL=noexiste` → clear failure with the `models-pull` hint.
- `make serve-up` → up and answering; `make serve-smoke` → **401** without token,
  **200** with token, `choice=to_do confidence=0.999`; `make serve-down` → stopped.
- `make test-integration` → **1 passed** with the real model.
- `make classify LABELS=examples/invox/labels.yaml TEXT="…"` → real classification.

## Decisions taken

- **`make ci` stays model-free** (fast, deterministic, offline): the gate tests
  logic with the injected fake engine; the real model is an opt-in integration
  target. Same pattern as `invox` and its STT.
- **The model is a shared resource** with an explicit pull step and a `MODEL`
  variable used symmetrically by every consuming target.
- **`laya-serve` is Laya's**; this repo launches and documents it, never wraps it.

## Known issues / open points

- `LAYA_API_KEY` is a single global key; per-consumer credentials would need a
  proxy in front.
- `LAYA_PRELOAD=1` loads every model named in `LAYA_MODELS`; the correct variable
  is `LAYA_MODELS` (not `LAYA_MODEL` — an early mistake that preloaded all three).
- The zero-shot accuracy on long texts and ten labels was ~52% (see the invox
  example); the eventual fix is a fine-tuned checkpoint, served unchanged.

## Next steps

- Serve a fine-tuned checkpoint by pointing `LAYA_MODELS`/the repo at the new
  weights; the contract and the clients do not change.
- Tag the first release once the surface settles.
